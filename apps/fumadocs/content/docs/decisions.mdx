Les choix techniques du projet, avec leur raison et la PR qui les a introduits. On ajoute une ligne quand une PR change la façon de travailler ou l'architecture, et on ne réécrit pas une décision remplacée : on en ajoute une nouvelle qui renvoie à l'ancienne.

## API et contrat

| Décision                                                                                                                                                          | Pourquoi                                                                                                            | PR                                                                                                                 |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| Le contrat OpenAPI `contrat/openapi.yaml` fait foi                                                                                                                | Web, mobile et back se calent sur un seul document ; le mobile peut développer sur un mock généré depuis le contrat | [#27](https://github.com/RobinSartini/EventsHub/pull/27)                                                           |
| Une route ajoutée est documentée dans le contrat, dans une PR dédiée mergée avant l'implémentation                                                                | La cheffe du contrat valide l'API avant le code, et le front connaît la forme des réponses à l'avance               | [#53](https://github.com/RobinSartini/EventsHub/pull/53), [#87](https://github.com/RobinSartini/EventsHub/pull/87) |
| Réponses JSON brutes, sans enveloppe `{ success, data }` ; pagination par `page`/`pageSize` et en-tête `X-Total-Count`                                            | Le mobile décode directement `[Event]` ; le total reste disponible sans changer la forme de la réponse              | [#53](https://github.com/RobinSartini/EventsHub/pull/53)                                                           |
| Erreurs au format `Error` du contrat, construites par les fabriques de `@/errors` ; erreurs de validation dans `details` par champ, erreurs globales sous `_form` | Un seul format d'erreur pour tous les clients, et plus d'erreurs recréées à la main dans chaque route               | [#72](https://github.com/RobinSartini/EventsHub/pull/72)                                                           |
| Le tri par distance se fait côté back, avant la pagination                                                                                                        | Un tri côté front ne trierait que la page reçue                                                                     | [#89](https://github.com/RobinSartini/EventsHub/pull/89)                                                           |
| Un événement annulé reste accessible par `GET /events/{id}` avec `status: "cancelled"`                                                                            | Quelqu'un qui a le lien ou qui était inscrit doit voir l'annulation, pas une page introuvable                       | [#100](https://github.com/RobinSartini/EventsHub/pull/100)                                                         |

## Back

| Décision                                                                                                                                          | Pourquoi                                                                                                        | PR                                                       |
| ------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| Routes rangées par feature, un fichier par endpoint ; tests rangés de la même façon (`tests/feature/<feature>/<route>.test.ts`)                   | Retrouver une route et son test sans parcourir de gros fichiers                                                 | [#54](https://github.com/RobinSartini/EventsHub/pull/54) |
| Imports internes du serveur via `@/` et `@tests/`                                                                                                 | Déplacer un fichier sans casser une chaîne de `../../..`                                                        | [#72](https://github.com/RobinSartini/EventsHub/pull/72) |
| Session Better Auth en cookie, plus un access token JWT de 15 min (EdDSA) obtenu par `POST /api/auth/refresh` et vérifiable avec `/api/auth/jwks` | Le web garde le cookie ; un client qui ne peut pas l'utiliser a un token court, vérifiable sans appel à la base | [#41](https://github.com/RobinSartini/EventsHub/pull/41) |
| Seules les routes d'auth du contrat sont exposées ; les autres routes Better Auth répondent 404                                                   | Elles contournaient nos validations (ex. `update-user` acceptait un nom vide)                                   | [#91](https://github.com/RobinSartini/EventsHub/pull/91) |
| Better Auth en 1.7                                                                                                                                | Corrige trois failles (1 critique, 2 hautes) signalées par l'audit                                              | [#82](https://github.com/RobinSartini/EventsHub/pull/82) |
| Retrait des intégrations générées jamais utilisées (Redis, files de jobs, Stripe, Sentry, S3, recherche, IA…)                                     | Moins de dépendances, de variables d'environnement et de services à lancer                                      | [#78](https://github.com/RobinSartini/EventsHub/pull/78) |
| Pas encore de migrations Prisma : `prisma db push` aligne la base sur le schéma                                                                   | Suffisant en développement tant qu'il n'y a pas de base de production à faire évoluer                           | [#78](https://github.com/RobinSartini/EventsHub/pull/78) |

## Outillage, Docker et CI

| Décision                                                                                                                                       | Pourquoi                                                                              | PR                                                                                                                 |
| ---------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| Une seule documentation, Fumadocs sous React Router (`apps/fumadocs`)                                                                          | Deux sites faisaient doublon sur le même port ; celui-ci suit la stack du front       | [#26](https://github.com/RobinSartini/EventsHub/pull/26)                                                           |
| `bun dev` lance tout : fichiers `.env`, PostgreSQL, schéma, données de démo, apps                                                              | Un nouvel arrivant démarre le projet en une commande                                  | [#78](https://github.com/RobinSartini/EventsHub/pull/78), [#83](https://github.com/RobinSartini/EventsHub/pull/83) |
| Architecture des images Docker choisie par `DOCKER_PLATFORM` (vide = celle de la machine)                                                      | L'équipe est à la fois sur Mac Apple Silicon et sur Windows                           | [#43](https://github.com/RobinSartini/EventsHub/pull/43)                                                           |
| Le web en Docker est servi par `serve`, sans nginx                                                                                             | La configuration nginx (CSP) bloquait l'app et ajoutait de la complexité pour une SPA | [#47](https://github.com/RobinSartini/EventsHub/pull/47)                                                           |
| Branche d'intégration `dev`, promue ensuite vers `staging` puis `main`                                                                         | Le travail en cours n'arrive pas directement sur `main`                               | [#59](https://github.com/RobinSartini/EventsHub/pull/59)                                                           |
| La CI tourne sur les PR et push vers `dev`, `staging` et `main`                                                                                | Avant, les PR vers `dev` n'étaient jamais vérifiées                                   | [#60](https://github.com/RobinSartini/EventsHub/pull/60)                                                           |
| Images Docker publiées sur GHCR à chaque push validé, taguées `<branche>-<sha>`                                                                | Déployer sans rebuild et revenir à une version précédente en une commande             | [#80](https://github.com/RobinSartini/EventsHub/pull/80)                                                           |
| Audit des dépendances et Trivy (dépôt et images) bloquants en sévérité haute ou critique ; exceptions justifiées et datées dans `.trivyignore` | Détecter les failles avant le merge et avant la publication d'une image               | [#80](https://github.com/RobinSartini/EventsHub/pull/80)                                                           |
| Trivy lancé depuis son image Docker épinglée par digest, pas via `trivy-action`                                                                | Les tags de l'action ont été compromis en 2026                                        | [#80](https://github.com/RobinSartini/EventsHub/pull/80)                                                           |
| Conteneurs exécutés en utilisateur non root                                                                                                    | Relevé par Trivy ; limite l'impact d'une faille dans l'app                            | [#80](https://github.com/RobinSartini/EventsHub/pull/80)                                                           |
